# Юніт-тестування: теорія та практика

##  Вступ

Юніт-тестування — це підхід до тестування програмного забезпечення, при якому перевіряються окремі частини коду (методи або класи) ізольовано від інших компонентів. Воно дозволяє швидко знаходити помилки, покращує якість коду та спрощує його підтримку.

---

##  Переваги та обмеження

### Переваги юніт-тестування:

* **Швидкість** — тести виконуються дуже швидко
* **Раннє виявлення помилок** — баги знаходяться ще під час розробки
* **Простота локалізації проблеми** — легко визначити, де саме помилка
* **Підтримка рефакторингу** — можна безпечно змінювати код
* **Документація** — тести показують, як повинен працювати код

###  Обмеження:

* Не перевіряє взаємодію між компонентами
* Не виявляє проблеми з конфігурацією або базою даних
* Потребує часу на написання та підтримку

---

###  Порівняння з інтеграційним тестуванням

| Критерій   | Юніт-тести        | Інтеграційні тести        |
| ---------- | ----------------- | ------------------------- |
| Рівень     | Окремі методи     | Взаємодія компонентів     |
| Швидкість  | Дуже швидкі       | Повільніші                |
| Залежності | Ізольовані        | Реальні залежності        |
| Надійність | Висока для логіки | Виявляє системні проблеми |

 Висновок: обидва типи тестування потрібні та доповнюють один одного.

##  Приклад класу

```csharp
public class Calculator
{
    public int Add(int a, int b)
    {
        return a + b;
    }

    public int Divide(int a, int b)
    {
        if (b == 0)
            throw new DivideByZeroException();
        return a / b;
    }

    public bool IsPositive(int number)
    {
        return number > 0;
    }
}
```

##  Юніт-тести (xUnit)

```csharp
public class CalculatorTests
{
    private readonly Calculator _calculator = new Calculator();

    // Add
    [Fact]
    public void Add_ValidNumbers_ReturnsSum()
    {
        int result = _calculator.Add(2, 3);
        Assert.Equal(5, result);
    }

    [Fact]
    public void Add_NegativeNumbers_ReturnsCorrectSum()
    {
        int result = _calculator.Add(-2, -3);
        Assert.Equal(-5, result);
    }

    // Divide
    [Fact]
    public void Divide_ValidNumbers_ReturnsQuotient()
    {
        int result = _calculator.Divide(10, 2);
        Assert.Equal(5, result);
    }

    [Fact]
    public void Divide_ByZero_ThrowsException()
    {
        Assert.Throws<DivideByZeroException>(() => _calculator.Divide(10, 0));
    }

    // IsPositive
    [Fact]
    public void IsPositive_PositiveNumber_ReturnsTrue()
    {
        bool result = _calculator.IsPositive(5);
        Assert.True(result);
    }

    [Fact]
    public void IsPositive_ZeroOrNegative_ReturnsFalse()
    {
        bool result = _calculator.IsPositive(0);
        Assert.False(result);
    }
}
```

##  Використання mock-об’єктів

###  Коли використовувати mock:

* Коли клас залежить від **бази даних**
* При роботі з **API або зовнішніми сервісами**
* Коли залежність **повільна або нестабільна**
* Для перевірки викликів методів (наприклад, чи був викликаний Save)

###  Коли можна обійтися без mock:

* Коли методи **чисті (pure functions)** і не мають залежностей
* Для простої бізнес-логіки (як у Calculator)
* Коли залежності легко створити і вони швидкі

---

##  Висновок

Юніт-тестування є важливою частиною сучасної розробки програмного забезпечення. Воно дозволяє забезпечити стабільність коду, швидко знаходити помилки та спрощує подальший розвиток проєкту. Використання разом із інтеграційним тестуванням дає найбільш ефективний результат. Mock-об’єкти допомагають ізолювати код і тестувати його незалежно від зовнішніх факторів.
