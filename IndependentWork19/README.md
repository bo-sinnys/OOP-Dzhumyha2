\# Самостійна робота №19



\## Тема: Фабрики + Singleton: заміна без змін клієнта



\---



\## Мета роботи



Навчитися застосовувати патерни \*\*Factory Method\*\* та \*\*Singleton\*\* для створення гнучкої системи, де клієнтський код залежить від абстракцій, а не від конкретних реалізацій, що дозволяє легко змінювати компоненти без зміни клієнта.



\---



\## Теоретичні відомості



\*\*Factory Method\*\* — це породжувальний патерн, який визначає інтерфейс для створення об'єктів, але дозволяє підкласам вирішувати, який саме клас інстанціювати. Це дозволяє зменшити зв’язність коду та підтримує принцип відкритості/закритості (OCP).



\*\*Singleton\*\* — це патерн, який гарантує існування лише одного екземпляра класу та надає глобальну точку доступу до нього.



\*\*Dependency Inversion Principle (DIP)\*\* — модулі високого рівня не повинні залежати від модулів низького рівня; обидва повинні залежати від абстракцій.



\---



\## Хід роботи



Було створено консольний застосунок мовою програмування C#, який реалізує систему доступу до даних з використанням патернів Factory Method та Singleton.



\### Реалізовано:



1\. \*\*Інтерфейс IDataAccess\*\*, який містить метод:



&#x20;  \* `GetData(string query)`



2\. \*\*Класи реалізації:\*\*



&#x20;  \* `SqlDataAccess` — імітація SQL-запитів

&#x20;  \* `NoSqlDataAccess` — імітація NoSQL-запитів

&#x20;  \* `XmlDataAccess` — імітація роботи з XML



3\. \*\*Абстрактний клас DataAccessFactory:\*\*



&#x20;  \* містить абстрактний метод `CreateDataAccess()`

&#x20;  \* містить метод `ExecuteQuery()`, який використовує створений об'єкт



4\. \*\*Конкретні фабрики:\*\*



&#x20;  \* `SqlDataAccessFactory`

&#x20;  \* `NoSqlDataAccessFactory`

&#x20;  \* `XmlDataAccessFactory`



5\. \*\*Клас DataManager (Singleton):\*\*



&#x20;  \* забезпечує єдиний екземпляр класу

&#x20;  \* дозволяє встановлювати фабрику

&#x20;  \* делегує виконання запитів



\---



\## Демонстрація роботи програми



У методі `Main` було:



\* отримано екземпляр `DataManager`

\* встановлено різні фабрики

\* виконано запити для кожного типу джерела даних



\### Результат виконання:



```

\[SQL] Виконання запиту: SELECT \* FROM Users

\[SQL] Виконання запиту: SELECT \* FROM Orders



\[NoSQL] Виконання запиту: { users: true }

\[NoSQL] Виконання запиту: { orders: true }



\[XML] Виконання запиту: <users></users>

\[XML] Виконання запиту: <orders></orders>

```



\---



\## Аналіз отриманих результатів



У ході виконання роботи було продемонстровано:



\* можливість зміни джерела даних без зміни клієнтського коду

\* слабку зв’язаність між компонентами системи

\* відповідність принципу DIP



Завдяки використанню Factory Method додавання нового типу джерела даних не потребує зміни існуючого коду, а лише створення нової фабрики.



Singleton дозволяє централізовано керувати доступом до системи даних.



\---



\## Висновок



У результаті виконання роботи було успішно реалізовано систему доступу до даних із використанням патернів \*\*Factory Method\*\* та \*\*Singleton\*\*.



Отримані знання дозволяють створювати гнучкі, розширювані та слабо зв’язані програмні системи, що відповідають сучасним принципам об’єктно-орієнтованого програмування.
